# EgelTools

## Install and automatic updates

- Development: <https://files.miro23.uk/egeltools/dev/EgelTools.user.js>
- Main: <https://files.miro23.uk/egeltools/main/EgelTools.user.js>

Every push to `dev` or `main` runs **Publish userscript**. Each hosted copy has update/download metadata pointing to its own branch. Userscript managers require a higher version to auto-update. Existing installations using the legacy stable URL must reinstall from their chosen branch URL to switch channels.

The publisher reads the committed userscript (`EgelTools.user.js` or the legacy lowercase filename), validates matching `@version` and `APP.version`, and changes only its hosted update/download URLs. Source files are not rewritten. Each branch keeps immutable releases under `<branch>/releases/<version>/EgelTools.user.js`; reusing a version with different content fails. The legacy stable URL and its release history remain untouched.

## Publish a release

1. For userscript changes, bump `@version` and `APP.version` together and add notes to `CHANGELOG.md`.
2. Run relevant checks and merge the change through a pull request into `dev`.
3. The Action publishes the merged branch automatically. Check its result and the public download.
4. For an explicit deployment or retry, run `scripts/deploy.sh dev` (or `main`). This publishes the latest remote branch head, not uncommitted local work. Reuse the version for documentation-only changes.

The Action can also be run manually on either branch. An older queued run is skipped if a newer commit is already the branch head. Publish to `main` only for major releases such as `1.0` or `2.0` (`1.0.0` or `2.0.0`), through a PR from `dev` into `main`. Retain feature branches after ordinary merges into `dev`; clean up released feature branches only after the major-release merge and successful deployment. See `CLAUDE.md` (or `AGENTS.md`) for the cleanup safeguards.

## Server setup

`servarr` runs the `egeltools-publisher` Docker container, built from `scripts/publisher/Dockerfile`. It runs as UID/GID 1001, with only these writable host mounts:

- `/var/www/files/egeltools/dev` → `/publish/dev`
- `/var/www/files/egeltools/main` → `/publish/main`

It has no Docker socket, host credentials, or checkout mounted. GitHub Actions uses a short-lived signed OIDC token; no repository deployment secret or self-hosted runner is needed. The service verifies GitHub's signature, issuer, audience, expiration, repository/owner IDs, workflow path, event and branch, then fetches that branch from GitHub and checks the signed commit before publishing. Repository code is never executed on the server.

Caddy forwards `/egeltools/deploy` to `egeltools-publisher:8094` over Docker network `egeltools-publishing`. Mutable channel downloads and `deployment.json` use `Cache-Control: no-store`; versioned branch releases use immutable caching. The container restarts automatically after a server restart.

To install/update the service from an approved checkout, run `scripts/setup-publisher.sh`. Caddy's `/data/filehost/Caddyfile` needs the routing and cache directives in `scripts/publisher/Caddyfile.fragment` inside its existing site block. Validate and reload Caddy after merging these directives. Updating publisher code requires this server setup step; normal userscript pushes do not.

Validation: `python3 -m unittest discover -s tests -p 'test_publisher.py'` (requires `PyJWT[crypto]==2.10.1`), plus `bash -n scripts/*.sh`.

## Install for development

1. Install a userscript manager such as Tampermonkey or Violentmonkey.
2. Create a new userscript.
3. Copy the contents of `EgelTools.user.js` into it and save.
4. Reload an open Grepolis game tab.

The script matches `https://*.grepolis.com/game/*` and runs without privileged userscript APIs (`@grant none`).

Chrome and Firefox are supported. A low-frequency mount check restores the bottom-left quick-tools dock if Grepolis rebuilds the UI.

## Current behavior

- Adds an always-visible Grepolis-style horizontal quick-tools dock fixed 10px from the bottom-left corner.
- The dock's blue EgelTools button opens and closes an accessible settings window built from Grepolis's native window-frame classes; the former left-menu settings launcher has been removed.
- While Administrator is active, the same dock contains **Show CFs**, **Trade times**, and **Party trades**. These cross-town tools and their action handlers are removed immediately when Administrator expires. The **Academy** button for the Academy Planner stays in the dock either way.
- The movable **Trade times** panel sorts all owned towns by distance from the currently selected town and shows each trade time as HH:MM:SS, calculated from the world speed and halved while Captain is active; hovering a time shows the island, distance, world speed, and Marketplace level. It switches towns on row click and supports Arrow Up/Down and W/S keyboard navigation while open. Its saved **MARKET** toggle, on by default, hides towns below Marketplace level 5 or with an unknown level. Each row has a **Trade** button that opens Grepolis's trade window for that target without switching the selected town. Its lock control can trade-lock a troop-building town, hiding it from this list and excluding it from resource-source trades; locks persist across reloads, can be removed manually, and release automatically after one resource falls by more than half the warehouse capacity from its post-lock high-water mark. Distances follow the in-game travel calculator: `island coordinate × 128 + the slot offset for the island type`, 64 lower on odd island columns. Island types and town slots come from the world's `towns.txt` and `islands.txt`, loaded once on first use (the FV island links share the same island download); until then, and for towns missing from those files, Grepolis's absolute town positions are used.
- The **Party trades** dock button shows the recommended-trade count from the current snapshot (for example **Party trades · 12**), also while the panel is open; the first snapshot is built in the background after loading. The compact, movable panel keeps its towns, amounts, and ordering fixed until the window is reopened or **Refresh** is clicked. Trade buttons show sending/sent status without rebuilding the list; displayed amounts stay fixed, with current resources and trader capacity checked before sending. Failed requests allow retrying; requests without confirmation stop after 30 seconds and keep both endpoints blocked across Refresh until a definitive late response or a matching new trade model arrives. Buttons sharing a busy source or destination show Waiting and automatically unlock after synchronization. Check outgoing trades before reloading if no confirmation arrives. Its panel covers city parties and theater performances. Enable **Exclude theaters** under **Settings → Party trades** to omit theater costs from recommendations and donor reserves. Towns with an underfunded idle celebration come first, ordered by the longest required donor route (shortest completion route first), followed by underfunded celebrations ending within the selected time window, ordered by remaining time. Click **Next 90 minutes** to open a small menu and set the window in whole minutes; applying it saves the preference and refreshes the plan. The default is 90 minutes. Route distance orders the donors. When the world speed is known, the plan is also timed: trades are only suggested when they make the town ready by the end of its current celebration or cut the wait after that end by at least 10%; otherwise the town shows how long it needs without trades. Recommendations cover city-party costs of 15,000/18,000/15,000 and theater costs of 10,000/12,000/10,000 wood/stone/iron. Both types share one town row, with stock and forecast income counted once across their deadlines, while enforcing a 500 minimum for every shipped resource; a smaller final deficit is safely rounded up to 500 when warehouse room and donor surplus allow it. Normal production, expected Villagers' Loyalty claims, warehouse capacity, and relevant ongoing inbound resource trades are included before a shortfall is shown.
- Shows the complete donor plan immediately for every urgent town. Suggested source towns keep both the next-party cost and their forecast city-party reserve, prioritize shorter routes for travel time, then complete deficit coverage for equal-distance sources, and are capped by the receiver's known warehouse space after loaded incoming deliveries and each donor's currently available merchant capacity, shared across all destination towns so a city cannot be overbooked. Unknown warehouse capacity produces no proposals, and warehouse limits leave uncovered deficits visible. Route distance is used for arrival-time ordering because the world's trade-speed setting scales every own-town route uniformly. Every useful donor is included until the shortfall is covered or safe sources run out, and any remainder is clearly reported.
- Adds an explicit **Trade** button to every donor proposal. Clicking sends exactly the displayed amounts after checking live source and destination models, source stock, merchants, trade locks, and receiver warehouse room including all loaded incoming shipments. Missing or invalid live information blocks submission; unavailable proposals are disabled. Sending and successful trades are disabled to prevent duplicate clicks; explicit server rejections can be retried. Lost or timed-out responses keep both endpoints blocked to prevent duplicate shipments; late callbacks and matching new trade models reconcile them. A success callback without an explicit error is accepted even if its payload has no success flag or trade ID. Successful shipments are tracked while the trade model synchronizes. The donor town ID is posted directly, so trading never changes the currently selected city.
- Adds a red horizontal line to Grepolis's floating toolbar trade list at the shipment that fills the dominant incoming resource (the resource with the largest total delivery) in the selected town. The line appears after that shipment when it exceeds the warehouse's live effective capacity by at most 2,000 resources, and before it for a larger overfill. If the dominant resource is already full, the line is before the first shipment. Smaller incoming resources never trigger the line or keep an alert active. The calculation reads capacity from Grepolis, follows the list's arrival order, ignores outgoing shipments and returning merchants, and refreshes as Grepolis updates the trade models.
- When a monitored incoming trade reaches the red line, plays one short chime and opens **Incoming trades** if it is closed. The affected town gets a red card and Warehouse alarm label; the window header and dock button show the alarm count (for example **Incoming trades · 1 alarm**). Alarm towns stay listed after their final delivery until **Dismiss alarm** is clicked or the dominant incoming resource has room again. All owned towns with loaded resource trades are monitored through their per-town trade collections while the game is open, even when another city is selected; a line before a shipment alerts on completion of its predecessor, or when that shipment itself lands if it is the first one and the warehouse still has room. An alarm stays while the next delivery would still overfill, and an alarm whose town stock has not caught up yet expires after 60 seconds. Audio is enabled by the first click or keypress in the game.
- The **Incoming trades** dock button opens a compact, floating 480 px window with a draggable header and a scrollable list of readable town cards. It lists every owned town receiving loaded incoming trades, with alarm towns first, then sorted by next arrival. Each live row shows current warehouse stock and capacity, the next-trade countdown, shipment count, incoming total and resource breakdown, and matching unit-ratio icons for each shipment (with a two-resource rounding tolerance). Different unit ratios show separate icons; unmatched loads show Custom, and identical unit costs may match multiple icons. Town names switch directly to that town. Selecting a town at the red line also plays the chime once per selection; remaining in the town does not repeat it.
- Automatically forecasts the untouched stock a city-party- or theater-capable town must reserve for both eligible celebration types. Idle towns protect the cost of a party they can start now; active-party towns account for normal hourly production, inbound shipments, and expected Villagers' Loyalty claims every 13 minutes (resource rewards multiplied by world speed) while rebuilding the next 15,000/18,000/15,000 party cost. A town with no safe spendable remainder is protected from donor recommendations.
- The dock's **Show CFs** button shows the number of listed towns (for example **Show CFs · 3**), refreshed every 10 seconds while the panel is closed, and opens a compact movable panel listing towns that can start a city party (academy level 30 and at least 18,000 effective storage capacity) or a theater performance (Theater built, academy level 30, and at least 12,000 effective storage capacity), while excluding celebrations already in progress. The capacity comes from Grepolis's town model, so Pottery and artifact bonuses such as Athena's Cornucopia are included automatically.
- Provides a single PartyTracker setting for the persisted, opt-in Olympic Games option. When enabled, Academy 30 towns can start them from the finder for 50 gold; the action is disabled when the displayed gold balance is insufficient.
- Switches directly to a town when its name is clicked. The City party, Theater, and enabled Olympics controls start their respective celebration with one explicit click when the required resources or gold are available; unavailable actions remain disabled and explain the missing cost on hover. With **All towns** selected, **All CF**, **All Theater**, and enabled **All Olympics** issue one native Administrator request per celebration type. When a town group is selected, clicking a bulk control shows a red warning and sends no request.
- Refreshes the celebration finder every 10 seconds while it is open and links each result directly to its town.
- While Captain is active, adds a side window to the farming-claim overview that is collapsed by default. Its badge counts every farming village below level 6, while the expanded list groups them into one island-overview link per island, opens that island's information window without changing the selected city or map position, and keeps the original level-0 sentinel handling.
- While Captain is active, adds compact trade and unlock/upgrade controls directly to every FV in an island overview. A successful unlock turns into an enabled upgrade control in place, without reopening the island window. Trade recalculates the selected town's demanded-resource stock and available merchant capacity when clicked, sends at most 3,000 resources, and disables itself below the 100-resource minimum. Level-6 upgrades are omitted and upgrades already in progress are disabled. The controls are removed on Captain expiry, and every request handler validates Captain again before submitting.
- Adds the original circular troop-queue button beside the god display. Its overview shows the total population consumed by every queued `UnitOrder`; each unit card keeps the queued unit count prominent with a smaller population value, while land and sea headings retain unit-count subtotals. Native unit icons appear inside the same movable parchment-style window used by the other EgelTools tools. The button keeps its original coordinates and only exists while Administrator is active; no button is added to Administrator's recruitment overview.
- Adds the **Recruit Optimizer** box to the Barracks and Docks. Unit targets are saved per town or per Grepolis or custom town group (**Save City**, **Save Group**); each unit row shows the target, the current total (present, outside, and queued units), and the missing amount, with a fill button that enters the missing amount capped at the recruitable maximum. The box also shows resource costs (available / required), total recruitment time, and free population before and after the plan, and opens the full **Recruitment Simulator**, which models research, spells, heroes, and building levels. It replaces the earlier per-unit totals above the unit list.
- Administrator's recruitment overview shows each town's saved target, current total, and missing units, and its **Fill troops** button fills in the missing units for the listed towns.
- With **Settings → Trade window: recruitment needs** enabled (default), Grepolis's trade window shows the resources the target town's recruitment plan still needs and can fill them in. When planned resources arrive, the delivery bell in the left icon column lists the delivery and, with **Settings → Notifications → Recruitment resources delivered**, a browser notification appears.
- The **Academy** dock button opens the Academy Planner: an overview of every town's research against a research template saved per town or town group, with researched, missing, and not-required research marked, also inside the Academy window.
- **Settings → Recruit Optimizer backup** exports and imports unit targets and the recruitment totals cache as a JSON file, resets them, or syncs them through a Google Apps Script web app you deploy yourself (web app URL and access key).
- Remounts and repositions the quick-tools dock when Grepolis rebuilds its UI during in-game navigation.
- Starts or resets a persistent collection timer when `#fto_claim_button` is pressed while the captain is active, and restores it safely after a browser reload while Grepolis initializes the captain UI.
- Uses the selected collection time's loyalty equivalent for the timer: 5/10 minutes → 10 minutes, 20/40 minutes → 40 minutes, 90 minutes/3 hours → 3 hours, and 4/8 hours → 8 hours.
- Adds a **Store 3k** control beside the farming-village **Collect** button. With Administrator active, one click calls Grepolis's native `store_iron_in_all_towns` action with `town_group_id: -1` to keep 28,000 silver and store 3,000 in every eligible town (both amounts are set under **Settings → Store silver**, and the label follows the amount), without changing the current town or selected town group. An interrupted response callback no longer leaves the button stuck.
- Plays the fixed FV claim sound in every open Grepolis tab when the collection timer expires. The small sound is bundled into the userscript, so playback does not depend on the sound server or connection state. The sound itself is fixed, but **Settings → Notifications** can turn it off and add a browser notification that opens the farming overview when clicked. When the separate GrepoAlerts userscript is installed, the running timer and the ready state also appear there.
- **Settings → Notifications** also turns the Incoming trades warehouse alarm popup and its chime on or off. Incoming trades marks resources whose warehouse will be full on arrival.
- Uses GRCRT's alarm as the default incoming-attack sound, or lets that alarm use a saved YouTube video link with Save, Test/Stop, and Default controls in EgelTools settings. Standard YouTube watch, share, Shorts, Live, and embed links are accepted.
- Detects incoming attacks through Grepolis's per-town `MovementsUnits` collections and supports case-insensitive muted-player names separated by newlines, commas, or semicolons, plus a minimum attacker-points threshold. Mutes are saved as they are typed. Names are normalized and can be resolved through the attacker ID or `home_town_id` owner when Grepolis supplies an encoded or incomplete name. An unidentified toolbar-only count stays silent while player mutes are configured and waits for detailed movement data; without mute rules, it remains a safe alarm fallback.
- Rejects outgoing, returning, and just-landed attack movements by normalizing Grepolis's boolean direction values, checking that the origin is not yours, and requiring generic `Attack` entries to have one of your towns as their destination.
- Baselines attacks already present while the page opens, so loading or reloading Grepolis does not sound the incoming-attack alarm.
- Can apply a 20-second grace period only during a configured daily time window, including overnight windows. An attack cancelled during that grace period does not sound the alarm.
- Cancels the timer and stops audio when the captain becomes inactive.
- Keeps the ON/OFF repeat button beneath the strategic-map button.
- Uses the existing farming-village alarm control (`.boerendorpKnop`) as the dismiss button, or adds a native-toolbar fallback with the same `bdfarmed.png` image when that button is absent.

## Privacy

EgelTools does not collect or store personal data. Its same-origin game and public-data requests stay on the active Grepolis world. The optional Recruit Optimizer Google Drive sync sends unit targets only to the Google Apps Script web app URL you enter. Alarm audio and UI images may contact `cdn.grcrt.net`, `gme.cyllos.dev`, `flasktools.altervista.org`, `gpit.innogamescdn.com`, or a user-selected audio host; optional YouTube alarm embeds contact `youtube-nocookie.com`. Those providers receive the user's IP address and normal browser request headers. This disclosure is also included directly in the userscript metadata shown by userscript managers.

Disable the standalone **Collect Alarm**, **PartyTracker**, and **Units in the queue** userscripts after installing this integrated version so duplicate controls and independent alarm instances do not run at the same time.

Farm village exchanges can be enabled with **Settings → Party trades → Include farm village trades** (Captain required). Recommendations use the base village ratio, strictly above 1, and only spend resources above celebration reserves and configured minimums. Each exchange uses one village, best ratio first, and the next village only tops up once the first one's 3,000 is used. Two-step chains through a middle resource are offered as one row with one button; the second step is sent after the first is confirmed. They share merchant/resource reservations with town trades and recheck availability before sending. After sending a village trade, reload to plan further trades involving that town; if confirmation is missing, check outgoing trades first.

Helena timing appears in the attack screen while she is assigned to the selected town. The world's conquest mechanic is detected automatically from `Game.features.command_version` (`new` means revolt, `old` means siege), with no selector or saved mode. The base duration is read automatically from the world's native settings (`Game.constants.game_config.revolt_delay_seconds` or `conquest_time_hours`). These values already include world speed; when unavailable, the estimate falls back to 24 hours divided by `Game.game_speed`. The estimate refreshes with native travel time and includes Helena's level bonus; it assumes a successful attack with Helena accompanying the army. Dates and times use your computer's local timezone.

In siege mode, selecting a colony ship shows the projected siege end if it lands successfully. The estimate also works without Helena; when she is present, it assumes she accompanies the colony ship and applies her level bonus. Siege mode omits the base-duration detail.

Attack windows include EgelTools **Zapper**, **Zap All**, and **Restore** controls. Non-cancellable movements are removed from the page. Zapper removes one clicked movement; Zap All asks before removing all visible rows. Closing the command list or pressing Restore restores manually removed rows still belonging to that list. These controls only change the list; **K** cancels its first visible cancellable command (ignored while typing). Disable the standalone Hide Non-Cancellable Revolts script to avoid duplicate controls.

Under **Settings → Attack movements**, **Hide non-cancellable movements** controls automatic row removal (on by default). Turning it off immediately restores automatically removed rows. The preference is saved, and Zapper, Zap All, and Restore remain available in either mode.

Trade times includes a saved sliding toggle in its title bar. It filters available trade capacity strictly above the threshold under **Settings → Trade times** (default **5,000**). Unknown capacity is excluded. Refresh recalculates current capacity.

Under **Settings → Culture overview**, **Show Orpheus** controls Orpheus status and transfer controls while Administrator is active. Enabled by default, the preference persists across reloads and takes effect immediately.

The Council of Heroes has an **Assign here** button that uses the game’s square “transfer in” tile, matching the native Cancel travel button, beside each owned hero’s native Assign/Unassign button, or beside the arrival bar and Cancel button while the hero is travelling; it moves to their left only when the right side is occupied (hover for the tooltip). It cancels an existing transfer or unassigns the selected hero before assigning them to the current city, with normal travel time. If another hero is assigned or incoming, a native confirmation popup explains their removal first. Heroes already here or incoming here, and heroes accompanying an army, cannot be reassigned through this button. An unconfirmed request blocks further transfers until refresh; check the hero status before retrying.
